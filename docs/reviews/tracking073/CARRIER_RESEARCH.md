## Proposed automatic data flow — design, NOT_IMPLEMENTED
- Owner-approved CRM binding per parcel AND leg: origin domestic / international freight / destination domestic, explicit carrier code and account identity, waybill, route, parcel allocation version and order links. Do not guess country/carrier from arbitrary tracking number.
- Carrier account settings and credentials server-side only. Provider fixed allowlist HTTPS hosts; no arbitrary customer URL fetching/SSRF. Customer never receives provider tokens, shipper phone, full addresses or proof-of-delivery photos by default.
- Webhook preferred where supported; authenticate according to actually documented/onboarded mechanism. Unauthenticated webhook is only a signal for authenticated API reread, never direct trusted delivered/location facts. Bound payload, timeout, retry, rate and cardinality; dedup verified carrier/account/waybill/event. Acknowledge only after durable accepted event/inbox transaction.
- Bounded scheduled reconciliation for active linked shipments, backoff/jitter on429/5xx, conditional reads where carrier supports them. Stop routine polling at terminal states subject to dispute window/carrier correction policy; retain observed time/event time to explain delayed scans. Never request all orders on every chat turn.
- Reject mismatched account/waybill/order binding; preserve unknown status as unknown; handle duplicates, out-of-order scans, clock/timezone discrepancies and corrections without silently rolling business stages backwards. Corrections audited with explicit policy; no carrier webhook financial mutation or customer receipt confirmation.
- Normalize read-only delivery substate separately from Order.stage: accepted/picked-up/in-transit/at-destination/out-for-delivery/delivered/attempt-failed/returned/unknown. Whole order delivered only after verified allocation coverage across all required parcels and destination legs, no conflicting partial/missing events. COMPLETED still requires existing customer/business authority. Refunds/cancellations/holds remain domain-owned.
- Shared customerOrderTracking projection should add whitelisted per-leg events, carrier source, carrier-observed time, last successful sync, delayed/unavailable distinction, carrier ETA labelled separately from staff estimate. Ask and Account both consume it via shared OrderTracking renderer. Do not display arrived Vietnam/customs/out-for-delivery until those facts actually exist; current domain only has broader processing milestones.
- Hybrid fallback: manual staff facts stay explicitly attributed; API outages retain last carrier observation marked stale. Never relabel manual information automatic or invent ETA/GPS. All private reads owner-only; no public/global/disk cache. Account-level locked/revoked guards preserved.
