Natural-language routing must choose a task/view, not execute its command. Text such as xem thành viên/xem chứng từ/hồ sơ/đề xuất thay đổi may open supported service disclosure with explicit user context; consequence buttons are existing native components, not model tools. Unknown or unsupported task returns exact dedicated screen link. Do not route a generic mention of membership/payment to automatic purchase or collection. Only one active service view avoids simultaneous listeners and overwhelming stacked forms; retain selected order/draft across view switches without cross-owner leakage.

Prioritization: receipt already supported; CustomerChanges is smallest route-independent new order task; membership opt-in component is self-contained but requires visual/UI-owner content review; document list needs explicit context contract before safe embedding; profile remains deliberate separate view with recipient reuse. No assertion all services are naturally completed by Ask until native service cases executed.
