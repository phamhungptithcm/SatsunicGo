## Common task information hierarchy

First row: human task/object title, operational status, decisive amount/quantity/date and one labeled permitted next action. Next row: customer/order relationship and exception/hold context. Open inline detail for editable form, proof/history and full technical identity. UUID is secondary selectable/copyable reference with full value available; do not invent commercial order numbers or hide identity required to disambiguate records. Short reference can support list scan but commands use verified full ID and version. Long names/reasons wrap in detail; compact list can clamp with accessible full detail, never remove refusal/hold/financial facts.

Use one task heading, one clear primary action, modest secondary refresh/filter actions, compact row→detail rather than tall form-card for every record. Icons supplement visible labels/status; icon-only secondary actions require accessible name/tooltip/focus. Do not put sensitive proof or role-target data in generic toast/log. Keep financial/destructive/admin action labels explicit and consequence/proof form intentionally expanded before submission; fewer clicks cannot remove confirmation.

## Label/navigation findings and smallest safe decisions

Confirmed CHANGES-label mismatch: Workspace says Thay đổi cần duyệt; ChangeQueue queries listWork orderChanges changeState accepted and heading Thay đổi đã được khách duyệt. Recommended Thay đổi chờ áp dụng; row status Khách đã duyệt and action Áp dụng thay đổi. Never imply staff approves customer's pending decision. Include payable/actualCosts before final apply; current cards emphasize raw order UUID and reason with no compact financial summary. UI projection already has proposal amounts, so no backend expansion required just for amounts.

ORDERS label Yêu cầu & báo giá fronts all orders including catalog and lifecycle queues. Recommended Đơn mua hộ for broad route, custom-only view can say Yêu cầu mới/Báo giá. Catalog kind-aware status must stay orderStageLabel; do not fall back generic deposit label in profiles/queue redesign. Purchasing unpaid vs eligible states should not share misleading paid caption.

FINANCE title currently Đối soát membership và ngoại lệ thanh toán but actual screen also renders transferReviews. Suggested Thanh toán & đối soát with labeled tabs/groups Chuyển khoản/Gói thành viên/Ngoại lệ; no transaction data loses context. Membership use Gói thành viên in everyday labels while keeping exact service identifiers internal. Changes/returns/refunds distinct; physical return and price adjustment don't promise refund.

## State contract for every route

Initial read uses bounded skeleton/status, not false empty. Successful empty has short task-specific explanation and one safe next action; error has inline cause scope/retry and doesn't retain actionable stale target. Pagination says additional loaded/page scope, not total. During mutation disable duplicate submit and target/filter switching or isolate it by generation; separate read-busy vs save-busy wording. Durable commit with response/read loss keeps stable operation/current result and says uncertain/saved appropriately. Dirty forms aren't silently replaced when filter/record/user changes; role/account switch clears private projections. Permission-limited empty differs from no records; unauthorized route links remain unoffered and server rejects writes. Long IDs/names/reasons/date/large money wrap without horizontal overflow390/768/1440, keyboard target order matches task order. Root/UI must test actual current loading/offline/error/unauthorized/stale/long-data, reduced motion/AT gates; no production/provider evidence inferred.
